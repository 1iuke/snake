让 System 协调业务流程

本课的胜利条件：ProgressModel 不再直接依赖存储层；ProgressSystem 协调 Model 与 StorageUtility，完成加载和一局结算。

1. 为什么现在值得引入 System

ProgressModel.record_completed_game() 当前同时承担：

  • 更新最高分与局数；
  • 把字段映射到存档键；
  • 调用 Utility 写盘；
  • 处理错误并发布事件。

这已经不是单纯的数据所有权，而是一段跨 Model 与 Utility 的业务流程。System 的价值是集中这类规则，而不是替代所有函数。

2. 创建 ProgressSystem

  1. 按 Ctrl + E 打开 QFramework 面板。
  2. 选择 创建 System。
  3. 名称输入 Progress，确认生成 ProgressSystem。
  4. 点击创建。

修改生成的 scripts/systems/progress_system.gd：

class_name ProgressSystem extends AbstractSystem

const NAME: String = "ProgressSystem"
const SCORE_SECTION := "scores"
const HIGH_SCORE_KEY := "high_score"
const STATS_SECTION := "stats"
const GAMES_PLAYED_KEY := "games_played"

var _model: ProgressModel
var _storage: StorageUtility

func get_system_name() -> String:
    return NAME

func init() -> void:
    _model = get_model(ProgressModel.NAME) as ProgressModel
    _storage = get_utility(StorageUtility.NAME) as StorageUtility
    assert(_model != null, "ProgressModel is not registered")
    assert(_storage != null, "StorageUtility is not registered")

    _model.high_score = maxi(
        0,
        _storage.load_int(SCORE_SECTION, HIGH_SCORE_KEY)
    )
    _model.games_played = maxi(
        0,
        _storage.load_int(STATS_SECTION, GAMES_PLAYED_KEY)
    )

func complete_game(final_score: int) -> void:
    _model.update_high_score(final_score)
    _model.games_played += 1
    _storage.set_int(SCORE_SECTION, HIGH_SCORE_KEY, _model.high_score)
    _storage.set_int(STATS_SECTION, GAMES_PLAYED_KEY, _model.games_played)

    var error := _storage.flush()
    if error != OK:
        push_error("Could not save progress: %s" % error_string(error))
        return

    _model.progress_saved.trigger()

3. 把 ProgressModel 缩回状态所有者

从 ProgressModel 删除：

  • 四个存档 section/key 常量；
  • _storage 字段；
  • init() 中的加载代码；
  • 整个 record_completed_game()。

最终保留：

class_name ProgressModel extends AbstractModel

const NAME: String = "ProgressModel"

var high_score := 0
var games_played := 0
var progress_saved := EasyEvent.new()

func get_model_name() -> String:
    return NAME

func init() -> void:
    pass

func update_high_score(candidate: int) -> void:
    high_score = maxi(high_score, candidate)

4. 注册 System

修改 snake_app.gd：

func init() -> void:
    register_utility(StorageUtility.new())
    register_model(ProgressModel.new())
    register_system(ProgressSystem.new())

QFramework 随后按 Utility → Model → System 初始化，所以 System 可以安全取得前两层。

5. Command 改为调用 System

修改 CompleteGameCommand.execute()：

func execute() -> void:
    var system := get_system(ProgressSystem.NAME) as ProgressSystem
    assert(system != null, "ProgressSystem is not registered")
    system.complete_game(final_score)

Controller 无需变化，仍然发送同一个 Command。调用路径变为：

Controller
  → CompleteGameCommand
  → ProgressSystem
  → ProgressModel + StorageUtility
  → progress_saved Event

6. 验证 Remote 树与行为

  1. 运行后展开 SnakeApp → System，确认存在 ProgressSystem。
  2. 确认启动时旧最高分与局数被加载。
  3. 完成一局，确认局数只增加一次、事件只触发一次。
  4. 重启游戏，确认进度仍然存在。
  5. 搜索 get_utility：业务脚本中应由 ProgressSystem 使用，ProgressModel 不再使用。
  6. 搜索 record_completed_game：应为零个结果。

7. System 不是什么

  • 不是所有节点都要访问的“万能 Manager”。
  • 不负责直接操作 HUD、Timer 或场景节点。
  • 不保存本应属于 Model 的长期业务状态。
  • 不包装只有一行且没有业务规则的局部函数。

System 的判断标准是：是否存在需要集中维护、可能由多个用例复用的业务规则或跨层流程。

8. 闭卷检索

为什么 ProgressSystem 能在 init() 中取得 Model 和 Utility？

Architecture 完成登记后按 Utility → Model → System 的顺序初始化，System 最后执行。

为什么存档键从 Model 移到了 System？

键映射属于进度持久化流程的协调细节；Model 只需拥有业务状态，不必知道如何映射到外部存储。

为什么 main.gd 不直接调用 ProgressSystem？

Controller 发送 Command 表达写入意图，Command 再协调 System，使交互入口保持统一且可复用。
