Lesson 13 · 约 35 分钟

只清理有证据的问题

这一课的胜利条件：修复当前项目的场景覆盖、重复状态副作用、依赖错误和编码问题，并通过一组发布前质量门。

1. 重构不是“把代码变复杂”

当前项目约两百行核心代码，不需要通用状态机框架、依赖注入容器或十几个 Manager。发布前重构只处理已经观察到的问题：

  • HUD 实例覆盖破坏了源场景布局。
  • 状态入口之外仍重复停止 Timer 和重绘。
  • 必需的 GameRules 没有启动时验证。
  • 底部提示包含损坏字符。
  • 全局音效使用了空间化播放器。

2. 清除 Hud 实例覆盖

hud.tscn 已定义 Full Rect，main.tscn 的 Hud 实例不应再保存自己的锚点、Grow 或 Offset。

  1. 打开 main.tscn，选中实例 Hud。
  2. 在 Inspector 的 Layout 中，对有还原箭头的覆盖属性逐项 Revert。
  3. 保存后用文本查看 main.tscn。

目标应只剩：

[node name="Hud" parent="." instance=ExtResource("...")]

不应紧跟 anchors_preset、anchor_*、offset_* 或 grow_*。实例将完整继承 hud.tscn。

3. 修正 Hud 源场景内部布局

打开 hud.tscn，选中 Margin，应用 Full Rect，并确保四个 Offset 都为 0。当前出现的 offset_right = 640、offset_bottom = 85 是额外尺寸，不是右/下边距。

真正的边距保留在 Theme Overrides：

Margin Left  = 60
Margin Top   = 35
Margin Right = 60

4. 状态副作用只保留一个作者

set_game_state(GAME_OVER) 已负责停止 Timer 和重绘，因此 finish_game() 改为：

func finish_game() -> void:
    set_game_state(GameState.GAME_OVER)
    high_score = maxi(high_score, score)
    games_played += 1
    save_progress()

暂停输入中，删除 set_game_state(...) 之后多余的 queue_redraw()。规则是：状态导致的视觉与 Timer 副作用全部归状态入口管理。

5. 给必需依赖明确失败

rules 是主游戏必需依赖。若场景忘记赋值，当前代码会稍后报模糊的 null 错误。添加：

func _ready() -> void:
    if rules == null:
        push_error("SnakeGame requires a GameRules resource.")
        return

    randomize()
    # 其余初始化……

这不是为“不可能情况”堆防御代码，而是在场景与脚本的依赖边界提供可行动的错误信息。

6. 修复编码与音效语义

将损坏的 footer 文本换成纯 ASCII，避免再次受文件编码影响：

"ARROWS / WASD  |  SPACE PAUSE"

吃食物声音属于非空间化全局反馈。把 EatSound 从 AudioStreamPlayer2D 改为 AudioStreamPlayer，并同步类型：

@onready var eat_sound: AudioStreamPlayer = $EatSound

只有声音应随世界位置、距离和声像变化时才使用 2D 播放器。

7. 清理格式而不改变设计

对自己改动过的文件执行以下机械清理：

  • 函数之间保留两行空行，不保留五行以上空白。
  • games_played := 0 等运算符两侧留空格。
  • 长参数列表分行并保持缩进。
  • 删除已注释掉的旧实现和临时调试输出。

不要借机拆分稳定函数或重命名所有节点。每一行变更都应能对应一个实际问题。

8. 文件组织：现在不做大搬家

项目最终可采用：

game/       main.tscn, main.gd
actors/     food.tscn, food.gd
ui/         hud.tscn, hud.gd
data/       game_rules.gd, *.tres
audio/      *.wav, *.ogg

但发布前批量移动会产生大量路径变更，收益有限。当前文件数量很少，保持现状并记录未来结构即可。真正新增第二个角色或界面时，再按功能共置场景、脚本和资源。

9. 五道质量门

  1. 加载：Godot 编辑器打开项目无解析错误。
  2. 主流程：开始、得分、暂停、恢复、结束、重开均正常。
  3. 持久化：重启后最高分和局数仍在。
  4. 布局：Hud 实例没有覆盖，窗口变化时左右边距稳定。
  5. 资源：临时移除 Rules 时出现清楚错误；恢复后正常。

11. 闭卷检索

问题 1：为什么实例覆盖会让源场景修复看起来“不生效”？

加载实例时，实例保存的属性值会覆盖源场景默认值，因此修改源场景后仍可能看到旧布局。

问题 2：为什么 finish_game 不应再次 stop Timer？

GAME_OVER 状态入口已经拥有这个副作用；重复执行会让职责分散，未来修改时容易漏改一处。

问题 3：为什么现在不批量移动全部文件？

当前结构规模尚小，搬移只产生路径变更和回归风险；应在实际增长出现时按功能重组。
