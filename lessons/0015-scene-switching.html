给 Snake 添加标题场景

本课的胜利条件：项目先显示标题界面，点击“开始游戏”后，由 SceneTree 卸载标题场景并加载现有的 main.tscn。

1. 当前场景不是永远存在的对象

运行项目时，SceneTree 管理整棵节点树，其中一个节点是 current_scene。切换场景并不是隐藏旧画面，而是替换当前场景：

Title 被移出树并释放
        ↓
Game 被实例化并进入树

因此，保存在标题场景节点里的普通变量会随场景消失；写入 user:// 的数据不会。

2. 创建 title.tscn

  1. 创建新场景，根节点选 Control，命名为 Title。
  2. 对根节点执行 Layout → Full Rect。
  3. 添加 CenterContainer，同样设为 Full Rect。
  4. 在其中添加 VBoxContainer。
  5. VBox 下依次添加 Label、Button、Button。
  6. 命名为 TitleLabel、StartButton、QuitButton。
  7. 文本设为 SNAKE、开始游戏、退出，保存为 title.tscn。

CenterContainer 负责居中，VBoxContainer 负责纵向排列。不要再手动拖动其直接子节点。

3. 用信号表达按钮事件

给 Title 根节点附加 title.gd：

extends Control

const GAME_SCENE := "res://main.tscn"

func _on_start_button_pressed() -> void:
    var error := get_tree().change_scene_to_file(GAME_SCENE)
    if error != OK:
        push_error("Unable to open game scene: %s" % error_string(error))

func _on_quit_button_pressed() -> void:
    get_tree().quit()
  1. 选中 StartButton，在 Node → Signals 中双击 pressed()。
  2. 连接到 _on_start_button_pressed。
  3. 把 QuitButton.pressed() 连接到另一函数。

检查返回的 Error 能让错误路径或损坏场景立即给出明确诊断。

4. 把标题设为 Main Scene

  1. 选择 Project → Project Settings → Application → Run。
  2. 把 Main Scene 改为 title.tscn。
  3. 按 F5：应该先进入标题界面。
  4. 点击开始：应该进入原来的 Snake 游戏。
  5. 重新按 F5：应再次从标题界面开始。

你刚才区分过的知识现在参与真实设计：F6 运行当前编辑场景；F5 和导出程序都从 Main Scene 开始。

5. 观察生命周期

临时在 title.gd 中加入：

func _ready() -> void:
    print("Title entered tree")

func _exit_tree() -> void:
    print("Title exited tree")

运行并点击开始，观察 Output 的顺序。验证后删除这两段诊断代码。

6. 现在不要添加 Autoload

基本场景切换只需要 SceneTree.change_scene_to_file()。只有数据或服务确实需要跨越多个场景长期存活时，才考虑 Autoload，例如音乐播放器、会话配置或复杂转场控制器。

当前最高分已经保存在 user://；仅为“跨场景”再创建全局管理器，并不会带来实际收益。

7. 闭卷检索

切换场景后，旧场景节点里的普通变量怎样了？

旧场景被移出 SceneTree 并释放，其节点和普通成员状态一同消失。

为什么最高分仍然存在？

它已经写入 user://，生命周期独立于当前场景实例。

为什么本课不需要 Autoload？

需求只是替换当前场景，SceneTree 已直接提供该能力，没有必须跨场景存活的新对象。
