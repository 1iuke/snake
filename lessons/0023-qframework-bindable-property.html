QFramework 08 · v0.4.1 · 约 35 分钟

让最高分自己通知 HUD

本课的胜利条件：score_changed 只负责本局分数；BestLabel 直接订阅 ProgressModel.high_score，最高分改变时自动刷新。

1. BindableProperty = 值 + 变更事件

当前最高分由裸整数保存，调用方还要记得通知 UI。BindableProperty 把二者组合：

high_score.value = 50
        ↓ 值确实发生变化
自动通知所有订阅者

重复赋相同值不会触发事件；这由 QFramework v0.4.1 的属性 setter 保证。

2. 修改 ProgressModel

把：

var high_score := 0

改为：

var high_score := BindableProperty.new(0)

同步修改更新规则：

func update_high_score(candidate: int) -> void:
    high_score.value = maxi(int(high_score.value), candidate)

games_played 暂时仍是整数，因为当前没有界面需要对它持续响应。不要为了统一外观而批量包装所有字段。

3. 修正 ProgressSystem 的读写

加载初始值时使用无事件赋值：

_model.high_score.set_value_without_event(
    maxi(0, _storage.load_int(SCORE_SECTION, HIGH_SCORE_KEY))
)

保存时读取 .value：

_storage.set_int(
    SCORE_SECTION,
    HIGH_SCORE_KEY,
    int(_model.high_score.value)
)

启动加载不是玩家操作产生的“变化”；HUD 稍后使用 register_with_init_value()，仍能立即拿到已加载值。

4. 修正 ProgressSummaryQuery

return {
    "high_score": int(model.high_score.value),
    "games_played": model.games_played,
}

Query 返回普通整数快照，不把 BindableProperty 或 Model 引用暴露给读取者。

5. 收窄 main.gd 的局部 Signal

把信号改为只传当前分数：

signal score_changed(new_score: int)

所有发射位置改为：

score_changed.emit(score)

main.gd 不再为了刷新 BestLabel 而读取最高分。它仍可取得 ProgressModel，因为需要订阅 progress_saved 并调用 update_high_score()。

6. 让 HUD 绑定最高分

在 hud.gd 添加 Model 引用：

var progress_model: ProgressModel

在 _ready() 中绑定：

func _ready() -> void:
    progress_model = SnakeApp.get_model(ProgressModel.NAME) as ProgressModel
    assert(progress_model != null, "ProgressModel is not registered")

    progress_model.high_score.register_with_init_value(
        _on_high_score_changed
    ).un_register_when_node_exiting_tree(self)

把原来的分数回调缩为：

func _on_snake_game_score_changed(new_score: int) -> void:
    score_label.text = "SCORE  %04d" % new_score
    animate_score()

新增最高分回调，并把原有新纪录判断与动画移进来：

func _on_high_score_changed(new_high_score) -> void:
    var value := int(new_high_score)
    best_label.text = "BEST  %04d" % value

    var is_initial_update := displayed_high_score < 0
    var is_new_record := (
        not is_initial_update
        and value > displayed_high_score
    )
    displayed_high_score = value

    if is_new_record:
        animate_new_record()
    else:
        best_label.modulate = BEST_NORMAL_COLOR

保留你项目中实际的新纪录动画函数名；若函数名不同，迁移逻辑而不是机械复制名称。

7. 生命周期清理

自动注销已经随 HUD 的 tree_exiting 完成。在 _exit_tree() 中只需释放普通引用：

func _exit_tree() -> void:
    progress_model = null

8. 验证

  1. 启动游戏，BestLabel 应立即显示存档值，不需要先吃食物。
  2. 得到新纪录时，BestLabel 更新并播放原有黄色弹跳。
  3. 未超过最高分时，BestLabel 不重复触发新纪录动画。
  4. 当前 SCORE 仍随每次吃食物更新。
  5. 搜索 score_changed.emit：每处只传一个参数。
  6. 搜索 high_score 的数值访问：需要数值的位置都应使用 .value。

9. 何时不用 BindableProperty

  • 只在一个函数内使用的临时变量；
  • 没有任何观察者的局部状态；
  • 多个字段必须作为不可分割事务一起变化时；
  • 每帧高频变化且订阅通知没有价值的数据。

10. 闭卷检索

为什么加载时使用 set_value_without_event？

加载是在建立初始状态，不是一次运行时变化；HUD 随后通过 register_with_init_value 获取当前值。

为什么 Query 返回 high_score.value 而非 high_score？

查询应返回数据快照，不应暴露带写能力和订阅能力的 BindableProperty 对象。

为什么 games_played 暂时不改成 BindableProperty？

当前没有需要持续响应它的订阅者，包装后没有收益，只会增加访问语法。
