Lesson 14 · 核心课程收官 · 约 25 分钟

让 Snake 离开编辑器独立运行

本课的唯一成果：生成一个 Release 版本，把它复制到项目目录之外，确认游戏不依赖 Godot 编辑器也能完整运行。

1. 先区分三个概念

对象用途能否直接交给玩家
项目目录源场景、脚本、资源与导入缓存不推荐
Export PCK/ZIP只导出项目数据，不含运行程序不能独立运行
Export Project导出优化后的运行程序与所需数据可以

类比 Unity：Godot 的 Export Project 接近 Unity 的 Build，而不是把工程文件夹打包发送。

2. 检查主场景

  1. 打开 Project → Project Settings → Application → Run。
  2. 确认 Main Scene 指向 main.tscn。
  3. 按 F6 只运行当前场景，再按 F5 运行项目，确认两者的含义不同。

F5 使用 Main Scene；导出后的程序也从 Main Scene 开始。编辑器当前打开哪个场景并不重要。

3. 安装 Export Templates

  1. 选择 Editor → Manage Export Templates。
  2. 安装与当前 Godot 版本完全匹配的模板。
  3. 如果已经显示 Installed，直接进入下一步。

编辑器负责开发，Export Template 是面向目标平台的精简运行程序。没有模板，项目能在编辑器中运行，却不能生成正式构建。

4. 创建 Windows Desktop 预设

  1. 打开 Project → Export。
  2. 点击 Add… → Windows Desktop。
  3. 本机常规 Windows 电脑保持 x86_64。
  4. 将 Export Path 设为 build/windows/Snake.exe。
  5. 首次练习保持 Export All Resources，不要提前手动筛资源。

export_presets.cfg 保存预设，通常可以纳入版本控制；凭据则保存在 .godot/export_credentials.cfg，不应公开分享。

5. 导出 Release，而不是 PCK

  1. 选择刚创建的 Windows Desktop 预设。
  2. 点击 Export Project。
  3. 关闭 Export With Debug，导出 Release 版本。
  4. 等待生成 Snake.exe；若旁边还有数据文件，分发时必须一起保留。

Export PCK/ZIP 只产生资源包，不是这次要交付的可执行游戏。

6. 做一次真正的“陌生环境”测试

  1. 新建一个不在项目目录中的临时文件夹。
  2. 把整个 Windows 构建复制进去，不要只复制你猜测需要的文件。
  3. 退出 Godot 编辑器，再双击 Snake.exe。
  4. 测试移动、暂停、吃食物、死亡、重开和声音。
  5. 创造最高分，关闭程序后重开，确认最高分仍在。

这一测试同时验证了两个重要路径：

res://  → 被打包的只读游戏资源
user:// → 玩家机器上的可写用户数据

因此你的最高分必须写入 user://，不能依赖项目目录。

7. 最小交付包

把构建输出压缩为 ZIP，再交给测试者。ZIP 中只包含运行游戏所需的文件，不要包含：

  • .godot/、脚本源码或课程 HTML；
  • 本机的 user://stats.cfg；
  • 导出凭据、证书或密码；
  • 项目的调试截图和临时文件。

8. 可选：把手工导出变成可重复命令

创建并保存预设后，可在 PowerShell 中使用：

& "Godot.exe" --path "E:\Workspace\GameDevelop\Godot\snake" `
  --export-release "Windows Desktop" "build\windows\Snake.exe"

预设名称必须与 Export 窗口完全一致。命令行导出不是另一套构建系统，它只是复用了 export_presets.cfg。

9. 收官验收

  • 程序可在 Godot 关闭时启动。
  • 主循环、暂停、重开、音效和 HUD 均正常。
  • 从不同目录启动也不丢失资源。
  • 重启程序后最高分仍存在。
  • ZIP 解压后无需安装 Godot 即可运行。

闭卷检索

为什么编辑器中能运行，仍可能无法导出？

编辑器自带开发运行环境；导出还需要与当前引擎版本和目标平台匹配的 Export Templates。

为什么不能只把 PCK 文件发给玩家？

PCK 主要包含项目数据，不包含能够独立启动这些数据的目标平台运行程序。

为什么必须把构建复制到项目外测试？

它能暴露意外依赖项目路径、遗漏构建文件以及把存档写入错误位置等问题。

主阅读

阅读 Godot 4.7 官方文档的 Exporting projects，重点看 Export Templates、Export Project 与命令行导出部分。
