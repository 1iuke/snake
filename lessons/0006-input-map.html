让游戏理解“动作”，而不是按键

这一课的胜利条件：代码只判断 move_up 等语义动作，同一动作同时接受方向键、WASD 和手柄输入。

3. 查看配置落在哪里

保存后，Input Map 会写入 project.godot 的 [input] 区域。它不是编辑器私有设置，而是项目的一部分，应随版本控制提交。

[input]

move_up={
"deadzone": 0.2,
"events": [Object(InputEventKey, ...), ...]
}

不要手写这段复杂序列化内容；使用编辑器维护即可。

4. 用动作事件替换键盘事件

完整删除当前的 _unhandled_key_input()，换成：

func _unhandled_input(event: InputEvent) -> void:
    if event.is_action_pressed("move_up"):
        queue_direction(Vector2i.UP)
    elif event.is_action_pressed("move_down"):
        queue_direction(Vector2i.DOWN)
    elif event.is_action_pressed("move_left"):
        queue_direction(Vector2i.LEFT)
    elif event.is_action_pressed("move_right"):
        queue_direction(Vector2i.RIGHT)
    elif event.is_action_pressed("pause_game"):
        if not game_over:
            paused = not paused
            queue_redraw()
    elif event.is_action_pressed("restart_game"):
        if game_over:
            new_game()

_unhandled_input 接收各种 InputEvent，不再限定为键盘。event.is_action_pressed() 判断当前事件是否匹配 Input Map 中的动作。

# 事件：某次输入抵达时检查
func _unhandled_input(event):
    if event.is_action_pressed("pause_game"):
        toggle_pause()

# 轮询：每个物理帧检查当前状态
func _physics_process(delta):
    var axis := Input.get_axis("move_left", "move_right")
    position.x += axis * speed * delta

蛇每次按键只排队一次方向，因此事件方式更合适。平台角色的连续移动通常使用轮询。

6. 为什么使用 _unhandled_input？

Godot 会按顺序分发输入，UI 控件有机会先消费事件。只有尚未被处理的事件才到 _unhandled_input()。这意味着以后添加文本框或菜单时，UI 可阻止游戏同时响应同一按键。

简化模型：_input 较早看到事件；GUI 随后有机会处理；_unhandled_input 只看到剩余事件。游戏玩法控制通常适合后者，全局调试快捷键可能使用前者。

8. 闭卷检索

问题 1：增加手柄支持后，为什么不需要修改 main.gd？

代码依赖语义动作而非设备事件；只需在 Input Map 中给现有动作添加手柄事件。

问题 2：蛇转向为何用事件，不用 is_action_pressed 持续轮询？

转向是离散意图，每次按下只应排队一次；持续轮询更适合按住期间连续发生的运动。

问题 3：_unhandled_input 相比 _input 有什么意义？

它只接收未被 UI 等较早阶段消费的事件，能避免操作界面时同时触发游戏玩法。
