命令负责写，事件描述结果

本课的胜利条件：完成一局后，由 Command 修改 Model；保存成功后 Model 触发 progress_saved，订阅者只根据这个事实作出响应。

1. 先读懂当前闭环

SnakeGame
  → send CompleteGameCommand(final_score)  写入意图
  → ProgressModel.record_completed_game()  修改业务状态
  → StorageUtility.flush()                 持久化
  → progress_saved.trigger()               已发生的事实

Command 用祈使含义命名：“完成这一局”。Event 用过去式事实命名：“进度已保存”。事件不知道谁会响应，也不命令某个 HUD 或成就系统做事。

2. 在 ProgressModel 定义事件

在 progress_model.gd 的状态字段附近添加：

var progress_saved := EasyEvent.new()

修改 record_completed_game() 的结尾：

var error := _storage.flush()
if error != OK:
    push_error("Could not save progress: %s" % error_string(error))
    return

progress_saved.trigger()

只有保存成功才广播 progress_saved。如果广播的是“状态在内存中已改变”，应该改用另一个准确名称，例如 progress_changed，并把触发位置放在状态修改之后。

3. 在场景中订阅，但不耦合发布者

在 main.gd._ready() 取得 Model 后添加：

progress_model.progress_saved.register(
    _on_progress_saved
).un_register_when_node_exiting_tree(self)

再添加临时诊断订阅者：

func _on_progress_saved() -> void:
    print(
        "Progress saved: best=%d, games=%d"
        % [progress_model.high_score, progress_model.games_played]
    )

un_register_when_node_exiting_tree(self) 把订阅生命周期绑定到场景节点。场景退出后，长期存在的 Model 不会继续调用已经释放的对象。

4. 为什么不手动在 _exit_tree() 注销

你当然可以保存 UnRegister 并手动调用，但框架已经提供与 Node 生命周期绑定的写法。它把“注册”和“何时失效”放在同一表达式中，更不容易漏掉。

5. 保留 Godot signal，不做二选一

事件范围选择
score_changed当前 Snake 场景 → 自己的 HUDGodot signal
progress_saved长期 Model → 任意跨层订阅者EasyEvent

QFramework Event 不是用来替换所有 Godot signal。节点之间天然可见、生命周期一致时，原生 signal 更直接；Architecture 内共享状态的跨层通知，EasyEvent 更方便。

6. CQRS 的最小含义

在本项目中先使用简化规则：

  • 写：Controller 发送 Command，不直接编排共享状态修改。
  • 通知：写操作完成后触发描述事实的 Event。
  • 读：订阅者从 Model 读取展示所需状态。

不要把 CQRS 理解为必须使用两套数据库或复杂消息总线；当前目标只是让读写意图清晰。

7. 验证与故障实验

  1. 运行并结束一局，Output 应只打印一次 Progress saved。
  2. 再开始并结束一局，局数应再增加一次。
  3. 临时把 StorageUtility.SAVE_PATH 改成不可写位置。
  4. 确认出现保存错误，并且不打印 Progress saved。
  5. 立即恢复正确路径，再验证正常保存。

这个实验验证的是事件语义：失败时没有发生“保存成功”这个事实，就不应触发同名事件。

8. 常见错误

  • 把事件命名为 save_progress：这是命令口吻，不是事实。
  • 在 Command 和 Model 中各触发一次：订阅者会重复响应。
  • 注册后不注销：Autoload Model 会保留指向已释放场景的 Callable。
  • 让 Event 回调再次发送同一 Command：可能形成递归反馈环。

9. 闭卷检索

为什么 progress_saved 要在 flush 成功后触发？

事件名称描述保存已经成功；失败时触发会向订阅者广播一个没有发生的事实。

为什么订阅要绑定 node exiting tree？

Model 生命周期长于场景；自动注销可防止长期发布者继续持有和调用已经离开 SceneTree 的订阅者。

为什么保留 score_changed 原生信号？

它服务于同一场景内部、生命周期一致的节点通信，原生 signal 更直接，不需要强行经过全局 Architecture。
