只迁移真正共享的数据

本课的胜利条件：把 high_score 和 games_played 迁移到 ProgressModel，同时让本局 score 继续留在游戏场景。

1. 先判断数据的生命周期

数据生命周期所有者
score一局游戏；重开归零main.gd
high_score跨局、跨场景、跨启动ProgressModel
games_played跨局、跨场景、跨启动ProgressModel
direction当前 Snake 场景实例main.gd

Model 不是“变量收纳箱”。判断标准是数据是否具有共享业务语义，而不是代码能否移动。

2. 用生成器创建 ProgressModel

  1. 按 Ctrl + E 打开 QFramework 面板。
  2. 选择 创建 Model。
  3. 名称输入 Progress，确认预览类名为 ProgressModel。
  4. 点击创建；生成路径以面板预览为准。

将生成脚本调整为：

class_name ProgressModel extends AbstractModel

const NAME: String = "ProgressModel"

var high_score := 0
var games_played := 0

func get_model_name() -> String:
    return NAME

func init() -> void:
    pass

这里先保存状态，不做文件 I/O。存档能力会在下一课成为 Utility。

3. 在 SnakeApp 中注册

打开生成的 scripts/snake_app.gd：

class_name SnakeAppArchitecture extends Architecture

func init() -> void:
    register_model(ProgressModel.new())

register_model() 先按 NAME 放入字典；随后 Architecture 才会把 Model 加到运行时的 Model 节点并调用其 init()。

4. main.gd 获取 Model

删除原来的：

var high_score := 0
var games_played := 0

保留 var score := 0，并添加：

var progress_model: ProgressModel

在 _ready() 的最前面获取 Model：

func _ready() -> void:
    progress_model = SnakeApp.get_model(ProgressModel.NAME) as ProgressModel
    assert(progress_model != null, "ProgressModel is not registered")

    randomize()
    # 原有初始化继续……

Autoload 会先于当前场景进入树，所以 main.gd._ready() 执行时，注册流程应已结束。

5. 逐处替换共享数据访问

只替换这两个变量，不改变函数职责：

# load_progress()
progress_model.high_score = maxi(
    0,
    int(config.get_value("scores", "high_score", 0))
)
progress_model.games_played = maxi(
    0,
    int(config.get_value("stats", "games_played", 0))
)

# save_progress()
config.set_value("scores", "high_score", progress_model.high_score)
config.set_value("stats", "games_played", progress_model.games_played)

其余位置按同样规则替换：

score_changed.emit(score, progress_model.high_score)

progress_model.high_score = maxi(progress_model.high_score, score)
progress_model.games_played += 1

速度计算仍使用局部 score；HUD 信号也暂时保留。一次只改变数据所有权，不同时引入 Command、Event 和绑定。

6. 清理场景对 Model 的引用

func _exit_tree() -> void:
    progress_model = null

这不会删除 Model；Model 的所有者是 SnakeApp。这里只是让即将释放的场景明确丢弃引用。

7. 两层验证

  1. 运行游戏，在 Remote 树展开 SnakeApp → Model，确认存在 ProgressModel。
  2. 选中它，在 Inspector 中观察 high_score 和 games_played。
  3. 吃到食物并结束一局，确认数值随业务变化。
  4. 关闭再运行游戏，确认 ConfigFile 仍能恢复旧数据。
  5. 全局搜索独立的 var high_score 和 var games_played，应只在 Model 中定义。

8. 常见错误

  • Invalid get index：忘记在 SnakeApp.init() 注册 Model，或 NAME 不一致。
  • Parser Error：生成脚本尚未被 Godot 扫描，先等待脚本重新加载并修复首个报错。
  • 存档被清零：确保先取得 Model、再 load_progress()、最后 new_game()。
  • Remote 看见两个 Model：检查是否重复调用了 register_model()。

9. 闭卷检索

为什么 score 没有迁入 ProgressModel？

它只属于当前一局和当前游戏场景，重开即归零，暂时没有跨时间或跨对象共享的需求。

为什么存档函数暂时仍在 main.gd？

本课只改变数据所有权；文件 I/O 将作为独立的 Utility 迁移，避免一次改动多个架构维度。

是谁拥有 ProgressModel 的生命周期？

Autoload 的 SnakeApp Architecture；游戏场景只是通过名称取得并暂时引用它。
