QFramework 01 · v0.4.1 · 约 20 分钟

先让 Architecture 活起来

本课的胜利条件：创建 SnakeApp Architecture，运行游戏后在 Remote 场景树看到它及三层节点，并能解释它为什么不随 main.tscn 消失。

1. Architecture 在 Godot 中究竟是什么

它不是脱离引擎的“魔法容器”。你项目中的 Architecture 源码继承自 Node；生成的具体架构会注册为 Autoload，成为 /root 下长期存在的节点。

SceneTree.root
├── SnakeApp        ← Autoload Architecture
│   ├── System
│   ├── Model
│   └── Utility
└── SnakeGame       ← 当前场景

因此，Architecture 的跨场景生命周期来自 Godot Autoload，不是框架绕开了 SceneTree。

2. 用框架面板创建 SnakeApp

  1. 确认插件已启用：Project → Project Settings → Plugins 中 QFramework 为 On。
  2. 按 Ctrl + E，或打开编辑器底部的 QFramework 面板。
  3. 选择 创建 Architecture。
  4. 名称输入 SnakeApp，先检查面板显示的生成路径和 Autoload 名。
  5. 点击创建，不要手动复制框架内部脚本。

创建后，到 Project Settings → Globals → Autoload 确认存在且启用 SnakeApp。

3. 保持第一次 init() 为空

生成脚本应表达下面这个结构；文件位置以生成器实际结果为准：

class_name SnakeAppArchitecture extends Architecture

func init():
    pass

本课不注册 Model、System 或 Utility。先验证基础设施，再迁移业务，可以把“框架安装问题”和“业务重构问题”分开。

4. 用 Remote 场景树验证

  1. 按 F5 运行当前 Snake。
  2. 不要停止游戏，切回编辑器的 Scene 面板。
  3. 从 Local 切换到 Remote。
  4. 展开根节点并找到 SnakeApp。
  5. 确认它下面出现 System、Model、Utility。

如果只有 SnakeApp 而没有三层节点，检查 Debugger 报错；这些子节点由 Architecture._ready() 在运行时创建，所以 Local 树中看不到是正常的。

5. 从源码读出真实生命周期

打开 addons/qframework/framework/architecture/architecture.gd，找到 _ready()。按执行顺序回答：

  1. 先调用具体 Architecture 的 init()，让它登记对象。
  2. 创建三个分层节点。
  3. 依次挂载并初始化 Utility、Model、System。

关键区别：register 是把对象放入字典；随后框架才把它加入 SceneTree，并调用对象自己的 init()。

6. 给现有 Snake 画边界，但不迁移

现有内容候选位置本课是否移动
score / high_score / games_playedModel否
ConfigFile 存档读写Utility否
游戏状态转换规则System 候选否
方向输入与节点绘制Controller / View否

框架化的第一步不是搬代码，而是识别谁拥有数据、谁执行规则、谁接触节点。

7. 闭卷检索

为什么 SnakeApp 能跨场景存在？

它被注册为 Godot Autoload，是 SceneTree 根节点下独立于当前场景的 Node。

为什么本课不立刻把 score 搬进 Architecture？

先单独验证框架生命周期，避免把安装、初始化和业务迁移问题混在一次改动里。

Local 树没有三层节点，是否说明创建失败？

不是。三层节点由运行时的 _ready() 动态创建，应在 Remote 树中检查。
