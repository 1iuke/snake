把“完成一局”表达成 Command

本课的胜利条件：main.gd 只宣布“完成了一局，最终得分为多少”，由 CompleteGameCommand 找到 Model 并执行进度写操作。

0. 前置门禁：上一课必须只有一个存档入口

  1. 从 main.gd 删除 SAVE_PATH。
  2. 删除整个 load_progress() 与 save_progress()。
  3. 删除 _ready() 中的 load_progress() 调用。
  4. 全局搜索 ConfigFile 与 scores.cfg，业务代码中都应只命中 storage_utility.gd。

如果门禁未通过，先不要创建 Command。重复入口会让你无法判断数据究竟由谁加载。

1. Command 解决的不是“代码行数”

当前结束一局的交互链是：

SnakeGame.finish_game()
  → ProgressModel.record_completed_game(score)
  → 更新最高分与局数
  → StorageUtility 落盘

Controller 已经知道了具体 Model 及其写方法。Command 把这段写操作意图变成独立对象：

Controller → CompleteGameCommand → ProgressModel → StorageUtility

2. 生成 CompleteGameCommand

  1. 按 Ctrl + E 打开 QFramework 面板。
  2. 选择 创建 Command。
  3. 名称输入 CompleteGame，确认将生成 CompleteGameCommand。
  4. 点击创建。

修改生成的 scripts/commands/complete_game_command.gd：

class_name CompleteGameCommand extends AbstractCommand

var final_score: int

func _init(value: int) -> void:
    final_score = value

func execute() -> void:
    var model := get_model(ProgressModel.NAME) as ProgressModel
    assert(model != null, "ProgressModel is not registered")
    model.record_completed_game(final_score)

Command 不需要注册到 Architecture；它是一次性对象。send_command() 会在执行期间注入 Architecture，使其能够调用 get_model()。

3. Controller 只发送意图

将 finish_game() 中：

progress_model.record_completed_game(score)

替换为：

SnakeApp.send_command(CompleteGameCommand.new(score))

完整函数保持简洁：

func finish_game() -> void:
    move_timer.stop()
    set_game_state(GameState.GAME_OVER)
    SnakeApp.send_command(CompleteGameCommand.new(score))
    queue_redraw()

4. 不要为了 Command 而 Command

本课只封装“完成一局”，因为它包含：

  • 接受最终得分；
  • 更新最高分；
  • 增加已玩局数；
  • 触发持久化。

queue_direction()、绘制网格或播放一次声音仍留在场景脚本。它们是局部节点行为，没有必要制造命令对象。

5. 观察 send_command() 的注入过程

直接查看 QFramework 的 architecture.gd：

func send_command(command: AbstractCommand):
    command.architecture = self
    var ret_value = await command.execute()
    command.architecture = null
    return ret_value

所以 Command 只在执行期间持有 Architecture；执行结束后引用会被清空。这也是它适合表达一次性用例，而不适合保存长期状态的原因。

6. 验证

  1. 运行游戏并完成一局。
  2. 确认 games_played 只增加一次。
  3. 确认最高分与存档仍正常。
  4. 在 CompleteGameCommand.execute() 临时下断点，检查 final_score 与 architecture。
  5. 继续运行，验证后删除断点。
  6. 全局搜索 record_completed_game：调用方应只剩 Command。

7. 闭卷检索

为什么 Command 不需要 register_command()？

Command 是按需创建和执行的一次性用例对象，不是由 Architecture 长期持有的共享服务或状态。

Command 如何取得 ProgressModel？

send_command() 在执行前临时注入 Architecture，Command 再通过 get_model() 查询已注册 Model。

为什么不把每次方向输入都封装成 Command？

它目前只是当前场景实例的局部行为，没有共享业务写操作；引入 Command 只会增加间接层。
