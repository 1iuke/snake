Lesson 05 · 约 30 分钟

用自定义 Signal 解耦 HUD

这一课的胜利条件：把标题和分数绘制移入独立 Hud.tscn，主游戏只发出 score_changed，不直接调用 HUD。

1. 为什么还要拆？

当前 main.gd 同时负责蛇的规则、计时、食物、分数和界面绘制。项目很小时没有问题；但如果 HUD 以后增加动画、生命值或菜单，主游戏会越来越了解 UI 的细节。

# 紧耦合：主游戏必须认识 HUD
$Hud.set_score(score)

# 信号：主游戏只宣布事实
score_changed.emit(score, high_score)

Signal 表达的是“发生了什么”，不是“别人应该怎么做”。HUD 可以响应它，音效系统或成就系统以后也可以独立响应。

2. 创建 Hud Scene

  1. 新建 Scene，以 Node2D 为根节点，命名为 Hud。
  2. 附加空脚本 res://hud.gd。
  3. 保存为 res://hud.tscn。

将 hud.gd 写成：

extends Node2D

var score := 0
var high_score := 0


func _on_snake_game_score_changed(
    new_score: int,
    new_high_score: int
) -> void:
    score = new_score
    high_score = new_high_score
    queue_redraw()


func _draw() -> void:
    draw_string(
        ThemeDB.fallback_font,
        Vector2(60, 64),
        "SNAKE",
        HORIZONTAL_ALIGNMENT_LEFT,
        -1,
        36,
        Color("75e6a4")
    )
    draw_string(
        ThemeDB.fallback_font,
        Vector2(60, 105),
        "SCORE  %04d" % score,
        HORIZONTAL_ALIGNMENT_LEFT,
        -1,
        22,
        Color("eaf7ef")
    )
    draw_string(
        ThemeDB.fallback_font,
        Vector2(480, 105),
        "BEST  %04d" % high_score,
        HORIZONTAL_ALIGNMENT_LEFT,
        -1,
        22,
        Color("95a5b2")
    )

3. 把 HUD 实例放进主场景

  1. 重新打开 main.tscn。
  2. 从 FileSystem 面板将 hud.tscn 拖到 Scene 树中的 SnakeGame 上。
  3. 树应显示 SnakeGame/Hud，保存主场景。

这是编辑器内实例化：与代码中的 instantiate() + add_child() 结果相同，但实例关系直接保存进 main.tscn。

4. 声明并连接自定义 Signal

在 main.gd 顶部、extends Node2D 之后添加：

signal score_changed(new_score: int, new_high_score: int)

保存脚本，然后：

  1. 在 Scene 树选中 SnakeGame。
  2. 打开右侧 Signals 标签。
  3. 双击自定义的 score_changed。
  4. 接收节点选择 Hud。
  5. 方法名使用 _on_snake_game_score_changed。
  6. 点击 Connect 并保存场景。
检查：连接方向是 SnakeGame.score_changed → Hud._on_snake_game_score_changed。不要反过来。

5. 在状态改变处 emit

新游戏重置分数

在 new_game() 中，紧跟 score = 0 后添加：

score_changed.emit(score, high_score)

吃到食物更新分数

在 step_game() 的 if ate_food: 内，更新 score 和 high_score 后添加：

score_changed.emit(score, high_score)

信号参数会按声明顺序传给 HUD 回调。

6. 删除主场景旧 HUD

否则屏幕会绘制两遍文字：

  1. 在 main.gd 的 _draw() 中删除 draw_header()。
  2. 删除整个 draw_header() 函数。

7. 验收与调试

  1. 开始游戏：标题、SCORE、BEST 各显示一次。
  2. 吃到食物：SCORE 立即增加 10。
  3. 撞墙并重开：SCORE 回到 0，BEST 保留。
  4. 运行时查看 Remote 树：应有 SnakeGame/Hud。
  5. 打开 main.gd：它不应出现 $Hud 或 get_node("Hud")。

如果分数一直是 0，按顺序检查：是否 emit → 场景是否保存连接 → 回调参数是否一致 → 回调是否调用 queue_redraw()。

8. 事件链

Snake 吃到 Food
      ↓
main.gd 修改 score
      ↓
score_changed.emit(score, high_score)
      ↓  main.tscn 中的连接
Hud 回调保存数据
      ↓
queue_redraw() → _draw()

9. 闭卷检索

问题 1：主游戏是否知道 HUD 接收了信号？

不知道。主游戏只声明并发出事件；连接可以在不修改发出者的情况下添加、删除或更换接收者。

问题 2：为什么信号名用 score_changed，而不是 update_hud？

信号描述已发生的事实，而不是命令特定对象执行动作；这样 UI、声音和成就系统都能按需响应。

问题 3：emit 后为什么还要 queue_redraw？

emit 只调用订阅回调；HUD 数据虽已变化，但自定义 Canvas 绘制仍需请求下一次 _draw()。

加一分挑战

临时在 main.gd 的 _ready() 中用代码再连接一个匿名接收者：

score_changed.connect(
    func(value: int, _best: int) -> void:
        print("Score event: ", value)
)

观察同一个信号如何同时通知 HUD 和调试输出，然后删除这段临时代码。
