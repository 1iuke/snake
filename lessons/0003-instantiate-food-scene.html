把食物变成可实例化的 Scene

这一课的胜利条件：创建独立的 Food.tscn，在运行时实例化并加入 SceneTree，同时保持贪吃蛇玩法不变。

1. 先分清“蓝图”和“活对象”

const FOOD_SCENE := preload("res://food.tscn") # PackedScene
var food_visual := FOOD_SCENE.instantiate()     # Node 实例
add_child(food_visual)                          # 加入 SceneTree

它对应 Unity 的“加载 Prefab → Instantiate → 放进 Hierarchy”，但 Godot 加载的仍是普通 Scene。

2. 创建 Food Scene

  1. Godot 顶部菜单选择 Scene → New Scene。
  2. 选择 Other Node，搜索并创建 Node2D。
  3. 将根节点重命名为 Food。
  4. 给它附加脚本，路径设为 res://food.gd，模板选择 Empty。
  5. 将场景保存为 res://food.tscn。

把 food.gd 写成：

extends Node2D

func _draw() -> void:
    draw_circle(Vector2.ZERO, 10.0, Color("ff6b6b"))
    draw_line(Vector2(2, -9), Vector2(7, -15), Color("75e6a4"), 3.0)

这里让食物自己的原点成为圆心。位置不属于食物的固定定义，而由主场景中的实例决定。

3. 在主场景实例化

重新打开 main.tscn 和 main.gd，分四步修改。

① 预加载场景资源

在其他 const 附近加入：

const FOOD_SCENE := preload("res://food.tscn")

② 保存实例引用

在成员变量区域加入：

var food_visual: Node2D

③ 创建实例并加入树

将 _ready() 改为：

func _ready() -> void:
    randomize()
    food_visual = FOOD_SCENE.instantiate()
    add_child(food_visual)
    set_process(true)
    new_game()

顺序很重要：new_game() 会调用 spawn_food()，因此必须先创建 food_visual。

④ 让实例跟随网格坐标

在 spawn_food() 最后一行，即设置完 food 后加入：

food_visual.position = (
    BOARD_ORIGIN
    + Vector2(food) * CELL_SIZE
    + Vector2.ONE * CELL_SIZE / 2.0
)

4. 移交绘制职责

现在 Food Scene 已经自己绘制食物，主脚本不能再画一次：

  1. 在 main.gd 的 _draw() 中删除 draw_food()。
  2. 删除整个 draw_food() 函数。
  3. 保存并运行项目。
验收：屏幕上只有一个食物；蛇吃到它后，原来的 Food 实例移动到新网格；分数与碰撞逻辑保持不变。运行时切换到编辑器的 Remote 场景树，应看到 SnakeGame/ Food。

5. 发生了什么？

food.tscn --preload--> PackedScene
PackedScene --instantiate--> Food(Node2D)
SnakeGame --add_child--> Food 进入 SceneTree
spawn_food --position--> Food 移到网格中心

这次只创建一个实例并反复移动它。若是子弹或敌人，则会在每次生成时调用 instantiate()，产生多个互相独立的节点树。

6. preload 与 load

  • preload("固定路径")：解析脚本时加载；路径必须是常量，适合确定依赖。
  • load(path)：运行时按路径加载；适合路径动态决定的内容。

当前食物场景永远确定，所以使用 preload 更清晰。

7. 闭卷检索

问题 1：preload 得到的是屏幕上的 Food 节点吗？

不是。它得到 PackedScene 资源；调用 instantiate() 才创建节点实例。

问题 2：为什么 instantiate() 后还要 add_child()？

实例化只在内存中创建节点树；加入 SceneTree 后，它才获得树内生命周期并参与处理与绘制。

问题 3：为什么 Godot 不需要独立 Prefab 文件类型？

任何保存的 Scene 都是可加载和实例化的 PackedScene，因此同一机制已覆盖 Prefab 的职责。
