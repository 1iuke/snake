从三份文件读懂 Godot 项目

这一课的胜利条件：你能解释按下 F6 与 F5 为什么可能得到不同结果，并能指出当前贪吃蛇的“对象、行为、入口”分别在哪里。

1. 先建立一个不同于 Unity 的模型

Godot 游戏是一棵 Node 树。一棵保存下来的 Node 树叫 Scene；运行时所有 Scene 汇入 SceneTree。官方把 Node、Scene、SceneTree 和 Signal 列为四个核心概念。

Unity：Scene 与 Prefab
→
Godot：都用 Scene 表示
Unity：GameObject + Component
→
Godot：带类型的 Node + 子节点
Unity：Hierarchy
→
Godot：SceneTree

打开完整 Unity → Godot 速查表

2. 沿着启动链追踪项目

① project.godot：项目入口

[application]
config/name="Snake"
run/main_scene="res://main.tscn"

res:// 永远指向项目根目录。F5 运行项目时，Godot 读取 run/main_scene。因此这里决定了项目从哪一幕开始。

② main.tscn：场景与节点

[node name="SnakeGame" type="Node2D"]
script = ExtResource("1")

当前 Scene 只有一个名为 SnakeGame 的 Node2D。它没有 Unity 式 Transform 组件；二维变换能力来自 Node2D 这个节点类型本身。

③ main.gd：节点获得行为

extends Node2D

func _ready() -> void:
    new_game()

func _process(delta: float) -> void:
    # 每个渲染帧由引擎调用
    pass

func _draw() -> void:
    # queue_redraw() 后由引擎调用
    pass

extends Node2D 表示这个脚本扩展 Node2D。以下划线开头的这些函数是引擎约定的虚方法，不是我们手动调用的普通入口。

3. 生命周期：先记住三个点

  • _ready()：节点及其子节点进入 SceneTree 并准备完成后调用一次。
  • _process(delta)：按渲染帧调用；本项目用累加器把它降频成离散蛇步。
  • _draw()：负责自定义绘制；调用 queue_redraw() 请求下一次重绘。
为什么这里不是 _physics_process？
蛇按网格离散跳动，没有使用物理引擎求解碰撞。若是 CharacterBody2D 的连续移动和物理碰撞，才优先放进固定频率的 _physics_process()。

4. 现在动手：三分钟实验

  1. 在 Godot 中双击打开 main.tscn。
  2. 在 Scene 面板选中 SnakeGame，观察它的类型与已附加脚本。
  3. 按 F6：运行当前 Scene；关闭后再按 F5：运行项目。
  4. 暂时把 project.godot 的 run/main_scene 值读出来，不要修改。

5. 闭卷检索

先不回看上文，在脑中回答，再展开答案。

问题 1：当前项目最小的启动链是什么？

project.godot → main.tscn → SnakeGame(Node2D) → main.gd。

问题 2：Scene 更接近 Unity 的 Scene 还是 Prefab？

两者都是。Godot 用同一种 Scene 机制表达关卡、角色、菜单和可复用对象。

问题 3：为什么吃到食物后调用 queue_redraw()？

游戏状态已经变化，需要请求 CanvasItem 在下一绘制阶段再次执行 _draw()，把新状态呈现在屏幕上。
