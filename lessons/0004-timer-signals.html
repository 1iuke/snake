Lesson 04 · 约 25 分钟

用 Timer Signal 驱动蛇

这一课的胜利条件：删除手写的逐帧计时器，改用 Timer.timeout 信号触发蛇移动，并能说清“发出者是否需要知道接收者”。

1. 当前代码在轮询

func _process(delta: float) -> void:
    move_timer += delta
    if move_timer >= move_interval:
        move_timer -= move_interval
        step_game()

这段代码每个渲染帧都被调用，只为判断“时间到了没有”。它能工作，但 Godot 已经提供专门负责倒计时的 Timer 节点。Timer 到时会发出 timeout 信号。

2. Signal 的三个角色

关键价值是解耦：Timer 不需要知道蛇、方向或棋盘，只负责发出事件。接收方把一个可调用函数连接到信号。

3. 添加 MoveTimer 节点

  1. 打开 main.tscn，选中根节点 SnakeGame。
  2. 点击添加子节点，搜索 Timer。
  3. 将节点命名为 MoveTimer。
  4. 保持 One Shot 关闭、Autostart 关闭。
  5. 切换右侧 Signals 标签，双击 timeout()。
  6. 接收节点选择 SnakeGame，方法保持 _on_move_timer_timeout，点击 Connect。

连接会被保存到 main.tscn；编辑器会在 main.gd 生成回调函数。函数左侧的连接图标可以反查连接来源。

4. 用 @onready 获取子节点

找到现有的：

var move_timer := 0.0
var move_interval := start_speed

删除这两行，换成：

@onready var move_timer: Timer = $MoveTimer

$MoveTimer 是 get_node("MoveTimer") 的简写；@onready 把赋值推迟到节点进入 SceneTree、子节点可用之后。

5. 让 Timer 接管节拍

① 删除逐帧轮询

完整删除 _process(delta) 函数；在 _ready() 中删除不再需要的 set_process(true)。

② 新游戏时启动

在 new_game() 中删除原来的两行：

move_timer = 0.0
move_interval = start_speed

换成：

move_timer.start(start_speed)

③ 响应 timeout

把编辑器生成的回调改为：

func _on_move_timer_timeout() -> void:
    if not game_over and not paused:
        step_game()

④ 吃食物后加速

在 step_game() 中找到计算 move_interval 的那一行，替换为：

move_timer.wait_time = maxf(
    MIN_SPEED,
    start_speed - score * 0.0015
)

⑤ 游戏结束时停止

在 finish_game() 的第一行加入：

move_timer.stop()

6. 验收

  1. 运行项目：蛇应按原来的速度移动。
  2. 吃到食物：速度仍会逐渐增加。
  3. 按空格：暂停期间蛇不移动；恢复后继续。
  4. 撞墙：Timer 停止；按 R 后 Timer 重新启动。
  5. 搜索 _process：主脚本中应不存在这个函数。

7. 编辑器连接与代码连接

# 编辑器连接：记录在 main.tscn 中
[connection signal="timeout" from="MoveTimer" to="." method="_on_move_timer_timeout"]

# 等价的代码连接：适合运行时创建的节点
move_timer.timeout.connect(_on_move_timer_timeout)

本课用编辑器连接，是为了让你在 Signals 面板和场景文件中都看到关系。上一课的 Food 是运行时创建的；若 Food 需要连接信号，通常在实例化后用代码连接。

8. 闭卷检索

问题 1：Timer 如何知道该调用 step_game()？

它不知道。Timer 只发出 timeout；场景中保存的 signal connection 把该事件连接到主脚本回调，回调再调用 step_game()。

问题 2：为什么 $MoveTimer 要搭配 @onready？

脚本初始化早期，子节点可能尚不可用；@onready 在节点准备完成后获取 SceneTree 中的子节点。

问题 3：Signal 相比直接调用的主要价值是什么？

发出者无需持有或了解接收者，多个接收者也能独立响应，从而减少对象之间的耦合。
