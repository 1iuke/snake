Lesson 09 · 约 25 分钟

让最高分跨越游戏重启

这一课的胜利条件：游戏结束时把最高分写入 user://scores.cfg，重新启动项目后正确加载。

1. res:// 与 user://

res://
user://
项目资源目录
vs
当前用户数据目录
脚本、场景、纹理、规则
vs
存档、设置、缓存
导出后通常只读
vs
跨平台保证可写

开发时写入项目目录可能碰巧成功，但导出为安装包后 res:// 往往不可写。Godot 用 user:// 抽象 Windows、macOS、Linux 和 Web 各自的用户数据位置。

2. 为什么选择 ConfigFile？

本课只保存一个整数，不需要完整 JSON 存档系统。ConfigFile 原生支持“节 + 键值”的配置格式：

[scores]
high_score=120

它适合少量设置与简单进度；复杂世界状态再考虑 JSON、二进制序列化或专门的存档模型。

3. 定义存档路径

在 main.gd 的常量区域加入：

const SAVE_PATH := "user://scores.cfg"

路径集中定义可以避免加载与保存拼写不一致。

4. 编写加载函数

在 main.gd 中加入：

func load_high_score() -> void:
    var config := ConfigFile.new()
    var error := config.load(SAVE_PATH)

    if error == ERR_FILE_NOT_FOUND:
        return
    if error != OK:
        push_warning("Could not load high score: %s" % error)
        return

    high_score = maxi(
        0,
        int(config.get_value("scores", "high_score", 0))
    )

第一次运行没有文件是正常分支，不是故障。其他错误才输出警告。默认值 0 让旧文件缺少字段时仍可运行，maxi(0, ...) 防止负分进入状态。

5. 在正确时机加载

把 _ready() 调整为：

func _ready() -> void:
    randomize()
    food_visual = FOOD_SCENE.instantiate()
    add_child(food_visual)
    load_high_score()
    new_game()

必须在 new_game() 之前加载，因为 new_game() 会发出第一次 score_changed，HUD 应立即收到磁盘中的最高分。

6. 编写保存函数

func save_high_score() -> void:
    var config := ConfigFile.new()
    config.set_value("scores", "high_score", high_score)

    var error := config.save(SAVE_PATH)
    if error != OK:
        push_error("Could not save high score: %s" % error)

set_value() 只修改内存中的 ConfigFile；真正写盘必须调用 save()。

7. 在游戏结束时保存

把 finish_game() 改为：

func finish_game() -> void:
    move_timer.stop()
    game_over = true
    high_score = maxi(high_score, score)
    save_high_score()
    queue_redraw()

这里每局只写一次磁盘，足够简单。如果需要防止游戏中途退出丢失新纪录，可在最高分实际增加时保存，但要权衡写盘频率。

8. 验收

  1. 运行游戏，至少吃到一个食物，然后撞墙结束。
  2. 停止游戏，再次运行。
  3. BEST 应保留上局最高分。
  4. 在 Godot 菜单选择 Project → Open User Data Folder。
  5. 找到并打开 scores.cfg，确认数值正确。
  6. 删除该文件并重新运行，BEST 应安全回到 0，且没有红色错误。

9. 测试失败分支

将 scores.cfg 暂时改成无效内容，再运行游戏。目标不是让损坏文件自动修复，而是确认游戏不会崩溃，Debugger 会显示清楚的警告。测试后删除损坏文件。

边界意识：“文件不存在”是首次运行的正常状态；“文件存在但无法解析”才值得记录。不要把所有非 OK 错误都静默吞掉。

10. ConfigFile 与 GameRules 的区别

  • GameRules.tres：开发者制作并随游戏发布的静态内容，位于 res://。
  • scores.cfg：玩家运行游戏产生的个人数据，位于 user://。

两者都包含数据，但所有权、生命周期和写入权限不同。

11. 闭卷检索

问题 1：为什么不能把最高分写入 res://？

导出后的项目资源通常位于只读包中；user:// 才是 Godot 跨平台保证可写的用户数据目录。

问题 2：为什么 load_high_score 要在 new_game 前调用？

new_game() 会立即发出分数信号；提前加载可确保 HUD 第一次刷新就显示磁盘中的最高分。

问题 3：set_value 后为什么还要 save？

set_value() 只改变内存中的 ConfigFile 对象，save() 才把数据序列化并写入磁盘。

加一分挑战

在同一个配置文件加入累计游戏局数：

var games_played := int(config.get_value("stats", "games_played", 0))
config.set_value("stats", "games_played", games_played + 1)

先思考它应该在“开始一局”还是“结束一局”增加，并说明你的产品定义。
