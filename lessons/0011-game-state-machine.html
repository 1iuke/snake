Lesson 11 · 约 30 分钟

用一个状态替代两个布尔值

这一课的胜利条件：使用枚举统一表示 Playing、Paused、Game Over，使 Timer、输入和覆盖层只依赖一个可信状态。

1. 两个 bool 可以表达错误世界

var game_over := false
var paused := false

两个布尔值有四种组合：

game_overpaused含义
falsefalse正常运行
falsetrue暂停
truefalse游戏结束
truetrue语义冲突

最后一种组合本不应该存在，但数据结构允许它。枚举让“恰好处于一个状态”成为代码结构本身的约束。

2. 声明 GameState

删除两个 bool，改为：

enum GameState {
    PLAYING,
    PAUSED,
    GAME_OVER,
}

var game_state := GameState.PLAYING

枚举底层仍是整数，但命名值让状态分支可读，也避免随意组合。

3. 建立唯一状态入口

添加：

func set_game_state(next_state: GameState) -> void:
    if game_state == next_state:
        return

    game_state = next_state

    match game_state:
        GameState.PLAYING:
            move_timer.paused = false
        GameState.PAUSED:
            move_timer.paused = true
        GameState.GAME_OVER:
            move_timer.stop()

    queue_redraw()

以后不直接写 game_state = ...，统一调用这个函数。它是状态转换的单一入口，副作用集中在一处。

4. 新游戏进入 Playing

在 new_game() 中删除：

game_over = false
paused = false

把启动 Timer 的部分整理为：

set_game_state(GameState.PLAYING)
move_timer.start(rules.start_speed)

如果刚从 Game Over 重开，Timer 已停止；因此仍需要显式 start()。

5. 输入变成状态转换

把暂停与重开动作改为：

elif event.is_action_pressed("pause_game"):
    match game_state:
        GameState.PLAYING:
            set_game_state(GameState.PAUSED)
        GameState.PAUSED:
            set_game_state(GameState.PLAYING)

elif event.is_action_pressed("restart_game"):
    if game_state == GameState.GAME_OVER:
        new_game()

方向排队条件改为：

func queue_direction(next_direction: Vector2i) -> void:
    if (
        game_state == GameState.PLAYING
        and next_direction != -direction
    ):
        queued_direction = next_direction

6. Timer 与结束流程

回调改为：

func _on_move_timer_timeout() -> void:
    if game_state == GameState.PLAYING:
        step_game()

finish_game() 改为：

func finish_game() -> void:
    set_game_state(GameState.GAME_OVER)
    high_score = maxi(high_score, score)
    games_played += 1
    save_progress()

停止 Timer 和重绘已经由状态入口负责，不再在结束函数重复处理。

7. 覆盖层只读一个状态

在 _draw() 中：

if game_state != GameState.PLAYING:
    draw_overlay()

在 draw_overlay() 中：

var is_paused := game_state == GameState.PAUSED
var title := "PAUSED" if is_paused else "GAME OVER"
var hint := (
    "SPACE TO CONTINUE"
    if is_paused
    else "ENTER / R TO RESTART"
)

8. 完成机械检查

  1. 全局搜索 game_over，结果应为 0。
  2. 全局搜索独立变量 paused，除 move_timer.paused 和局部 is_paused 外不应存在。
  3. 正常运行、暂停、恢复、撞墙和重开各测试一次。
  4. 暂停时蛇停止；Food 呼吸仍继续——记录这个观察。
  5. 游戏结束时存档仍正确写入。

9. 业务暂停与 SceneTree 暂停

本课实现的是业务状态暂停：只暂停 MoveTimer，所以 Food 的 AnimationPlayer 和 HUD Tween 继续运行。

# 引擎级暂停
get_tree().paused = true

SceneTree 暂停会依据每个节点的 Process Mode 停止处理、物理、动画与音频。暂停菜单必须设为 When Paused 或 Always，才能接收恢复操作。小型网格游戏使用业务状态足够清晰；物理对象很多的游戏更适合引擎级暂停。

10. 为什么状态副作用要集中？

若暂停输入、结束函数和重开函数各自修改 Timer、Overlay、音效和动画，很容易遗漏某一项。集中入口让未来添加背景音乐或暂停菜单时，只改一个 match。

边界：这不是需要通用状态机框架的复杂项目。一个 enum、一个当前状态、一个转换函数已经足够；不要为了三个状态引入抽象基类或状态对象。

11. 闭卷检索

问题 1：enum 相比两个 bool 的核心优势是什么？

它只允许一个命名状态，无法表达“同时暂停且游戏结束”等无效组合。

问题 2：为什么所有转换都经过 set_game_state？

Timer、重绘等副作用集中在一个入口，避免每个调用点重复并遗漏状态同步。

问题 3：为什么 Food 在本课暂停时仍然呼吸？

本课只暂停了 MoveTimer，没有设置 SceneTree.paused；AnimationPlayer 仍按自己的 Process Mode 正常处理。
