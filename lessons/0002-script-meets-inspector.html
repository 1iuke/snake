Lesson 02 · 约 15 分钟

让脚本与 Inspector 协作

这一课的胜利条件：把蛇的初始速度变成 Inspector 可调参数，并能解释“脚本默认值”和“场景覆盖值”谁优先。

1. Scene 与 Script 各保存什么？

可以把一个 Godot 游戏对象看成两半：

Script
+
Scene
行为、方法、属性定义
+
节点组织、资源引用、属性取值
类似类的行为部分
+
类似可视化构造与序列化数据

脚本通过 extends Node2D 扩展根节点的能力；场景记录这个脚本附着在哪里，以及导出属性在该实例上的取值。官方建议把场景与根节点脚本视作一个可复用对象的两个部分。

2. @export 是什么？

@export var speed: float = 120.0
@export_range(0.05, 0.50, 0.01) var step_interval := 0.16

@export 让成员显示在 Inspector，并让取值随 Scene 或 Resource 一起保存。@export_range 进一步给 Inspector 一个最小值、最大值和步长。

Unity 映射：它的使用体验接近序列化字段，但不要把它只理解成“显示在 Inspector”。导出值也是场景数据的一部分；同一脚本附着到不同场景或实例时，可以保存不同取值。

3. 动手：把蛇速暴露给 Inspector

  1. 在 Godot 的 Script 工作区打开 main.gd。
  2. 找到 const START_SPEED := 0.16，替换为：
## 两次移动之间的秒数；越小越快。
@export_range(0.05, 0.50, 0.01) var start_speed := 0.16
  1. 把文件中另外两处 START_SPEED 改成 start_speed。
  2. 保存脚本，切回 2D 工作区，选中 Scene 面板中的 SnakeGame。
  3. 在 Inspector 顶部找到 Start Speed，先设为 0.40 并运行，再设为 0.08 并运行。

预期结果：0.40 时移动明显更慢，0.08 时明显更快；不需要再次修改脚本逻辑。

4. 两层取值规则

# main.gd：脚本默认值
@export var start_speed := 0.16

# main.tscn：如果你在 Inspector 改为 0.40，场景会保存覆盖值
start_speed = 0.4

加载 Scene 时，Godot 先构造节点与脚本，再应用场景保存的属性。因此：

  • 没有覆盖值：使用脚本默认值。
  • Inspector 改过并保存：场景值覆盖脚本默认值。
  • 点击 Inspector 属性旁的还原箭头：删除覆盖，重新跟随脚本默认值。
容易踩坑：在 _init() 中读取导出属性，可能只能读到脚本默认值，因为场景覆盖值尚未应用。需要场景配置值时，通常在 _ready() 或更晚读取。

5. 闭卷检索

问题 1：@export 是否会让变量变成全局变量？

不会。它仍属于该脚本实例；只是能被 Inspector 编辑，并被场景或资源序列化。

问题 2：脚本默认 0.16，Scene 保存 0.40，运行时是多少？

0.40。场景实例保存的覆盖值优先；还原属性后才重新使用 0.16。

问题 3：为什么设计师调速度不需要改业务代码？

脚本定义规则和允许范围，Scene 保存具体配置；行为与配置由导出属性连接。
