用 Control 构建自适应 HUD

这一课的胜利条件：删除 HUD 的手写文字绘制，改用 Control、MarginContainer、HBoxContainer 和 Label，缩放窗口时布局保持稳定。

1. 2D 世界与 UI 是两套布局模型

Node2D
Control
位置、旋转、缩放
vs
矩形、锚点、偏移
游戏世界对象
vs
界面元素
手动或物理移动
vs
由 Container 自动排布

当前 HUD 用固定坐标 draw_string(Vector2(60, 64), ...) 绘制。它看起来正确，却没有利用 Godot 的 UI 布局、主题、焦点和可访问性能力。

2. 将 Hud 根节点改为 Control

  1. 打开 hud.gd，先把第一行改为 extends Control 并保存。
  2. 打开 hud.tscn，右键根节点 Hud，选择 Change Type，改为 Control。
  3. 选中 Hud，在 2D 顶部 Layout 菜单选择 Full Rect。
  4. Inspector 将 Mouse → Filter 设为 Ignore，避免纯显示 HUD 截获玩法输入。

Full Rect 把四个锚点放到父级四角，并将相应偏移设为 0。窗口变化时 Hud 的矩形跟随视口。

3. 建立布局树

在 Hud 下按以下层级添加节点：

Hud (Control)
└── Margin (MarginContainer)
    └── Row (HBoxContainer)
        ├── TitleLabel (Label)
        ├── Spacer (Control)
        ├── ScoreLabel (Label)
        ├── Gap (Control)
        └── BestLabel (Label)

配置：

  1. 对 Margin 选择 Layout → Full Rect。
  2. 在 Margin 的 Theme Overrides → Constants 中，把 Left/Right 设为 60，Top 设为 35。
  3. 选中 Spacer，Horizontal Size Flags 勾选 Fill + Expand。
  4. 将 Gap 的 Custom Minimum Size X 设为 40。
规则：Control 一旦成为 Container 的直接子节点，它的位置和尺寸就由 Container 管理。不要拖动 Row 内的 Label；用 Size Flags、最小尺寸和容器主题常量表达布局意图。

4. 配置三个 Label

分别设置 Text：

TitleLabel  → SNAKE
ScoreLabel  → SCORE  0000
BestLabel   → BEST  0000

在各自 Inspector 的 Theme Overrides 中设置：

  • TitleLabel：Font Sizes → Font Size = 36；Font Colors → Font Color = #75e6a4
  • ScoreLabel：Font Size = 22；Font Color = #eaf7ef
  • BestLabel：Font Size = 22；Font Color = #95a5b2

右键 ScoreLabel 和 BestLabel，启用 Access as Unique Name。节点名称旁会出现百分号标记。

5. 用节点引用替换 _draw()

把 hud.gd 完整替换为：

extends Control

@onready var score_label: Label = %ScoreLabel
@onready var best_label: Label = %BestLabel


func _on_snake_game_score_changed(
    new_score: int,
    new_high_score: int
) -> void:
    score_label.text = "SCORE  %04d" % new_score
    best_label.text = "BEST  %04d" % new_high_score

不再保存重复的 score 状态，也不再调用 queue_redraw()。Label 的 text 改变时，它会自行更新最小尺寸并触发布局。

6. %Name 与 $Path

$Margin/Row/ScoreLabel  # 依赖完整树路径
%ScoreLabel             # 依赖场景内唯一名称

HUD 的布局层级可能增加 Panel 或动画容器。唯一名称允许内部重排而不改脚本路径。它只在所属 Scene 范围内保证唯一，不是全局查找。

7. 验收窗口适配

  1. 运行游戏，确认三个文本只显示一次。
  2. 吃食物后，ScoreLabel 正确更新。
  3. 拖动游戏窗口边缘改变宽度。
  4. SNAKE 应保持左侧边距，分数区域应保持右侧边距。
  5. 选中 Row 内 Label 尝试拖动，观察 Container 如何接管位置。
  6. Remote 树中展开 Hud，确认完整 Control 节点层级。

8. Anchors 与 Containers 的职责

  • Anchors：决定一个 Control 的边缘相对父级哪个位置。
  • Offsets：从锚点位置再偏移多少像素。
  • Containers：根据子节点最小尺寸和 Size Flags 自动排列直接子节点。
  • Theme：提供字体、颜色、间距和样式；可局部覆盖，也可整棵 UI 共享。

9. 闭卷检索

问题 1：为什么不应该手动拖动 HBoxContainer 的直接子节点？

Container 会根据最小尺寸、Size Flags 和主题间距重新计算直接子节点的位置，手动矩形值会被覆盖。

问题 2：Full Rect 实际改变了什么？

它把四个锚点对齐父级四边，并把相应偏移设为 0，使 Control 的矩形随父级尺寸变化。

问题 3：%ScoreLabel 相比完整 $ 路径有什么优势？

它依赖场景内唯一名称而非完整层级，因此重排中间布局节点时，脚本引用不必跟着修改。

加一分挑战

将 Gap 删除，改用 Row 的 Theme Overrides → Constants → Separation 控制所有相邻元素间距。比较两种方法：统一间距适合 Separation；只在某一处留白适合 Spacer 或固定最小尺寸。
