把组合读取表达成 Query

本课的胜利条件：progress_saved 发生后，场景通过 ProgressSummaryQuery 获得只读进度快照，而不是自己组合多个 Model 字段。

1. Query 是读取用例，不是 Model 的替代品

Command：我要改变什么？  → 写
Query：  我想知道什么？  → 读
Event：  什么已经发生？  → 通知

Query 适合组合、转换或跨多个来源的读取。像 progress_model.high_score 这样的单字段读取通常无需封装，否则只是增加跳转。

2. 生成 ProgressSummaryQuery

  1. 按 Ctrl + E 打开 QFramework 面板。
  2. 选择 创建 Query。
  3. 名称输入 ProgressSummary，确认生成类名与路径。
  4. 点击创建。

修改 scripts/queries/progress_summary_query.gd：

class_name ProgressSummaryQuery extends AbstractQuery

func do() -> Dictionary:
    var model := get_model(ProgressModel.NAME) as ProgressModel
    assert(model != null, "ProgressModel is not registered")

    return {
        "high_score": model.high_score,
        "games_played": model.games_played,
    }

与 Command 一样，Query 是一次性对象，不需要注册。send_query() 会临时注入 Architecture。

3. 在事件回调中执行 Query

把 main.gd 的临时诊断回调改为：

func _on_progress_saved() -> void:
    var summary: Dictionary = await SnakeApp.send_query(
        ProgressSummaryQuery.new()
    )
    print(
        "Progress saved: best=%d, games=%d"
        % [summary.high_score, summary.games_played]
    )

使用 await 是因为 QFramework v0.4.1 的 send_query() 会等待 query.do()。当前查询同步完成，但调用方式同样兼容未来的异步查询。

4. 为什么返回快照而不是 Model

如果 Query 直接返回 ProgressModel，调用方仍能修改它，读取边界形同虚设。返回新的 Dictionary 后，调用方拿到的是所需数据快照：

  • 只暴露这次读取需要的字段；
  • 不会把 Model 本身交给外部；
  • 未来可在 Query 内组合多个 Model 或 System。

Dictionary 适合当前小例子；大型项目可改用带类型的结果对象。

5. 不要删除 progress_model 引用

main.gd 目前仍需：

  • 订阅 progress_model.progress_saved；
  • 向局部 HUD 信号提供最高分；
  • 在吃到食物时更新最高分。

因此本课不为了“纯 CQRS”强行移除 Model 引用。架构规则服务于真实复杂度，而不是追求形式上的零直接访问。

6. 验证

  1. 运行游戏并完成一局。
  2. 确认 Output 的最高分和局数正确。
  3. 在 Query 的 do() 中下断点，观察 Architecture 已被注入。
  4. 确认 Query 内没有修改 Model 的语句。
  5. 验证后删除断点。

7. 什么时候不该创建 Query

读取需求建议
读取一个公开字段直接读取
组合多个 Model 字段考虑 Query
包含筛选、排序、聚合使用 Query
会修改任何业务状态改用 Command

8. 闭卷检索

为什么 Query 不应该修改 Model？

Query 表达读取；若同时写入，调用方无法仅凭类型判断副作用，读写边界会失去意义。

为什么不为每次 high_score 读取都创建 Query？

单字段读取没有组合或转换复杂度，封装只增加间接层和文件数量。

为什么 Query 返回快照而不是 Model？

快照限制暴露范围，并避免把可修改的共享状态引用交给读取方。
