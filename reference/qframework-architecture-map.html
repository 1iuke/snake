Architecture 分层速查

角色负责不负责
Controller接收输入、协调用例、更新 View保存共享业务状态
Model业务数据、数据约束、状态变更直接操作界面节点
System跨模型的业务规则与流程渲染具体 UI
Utility无业务语义的基础能力决定游戏规则
Command表达一次写操作承载长期状态
Query表达一次读操作修改业务状态
Event广播已经发生的事实命令特定对象执行动作

v0.4.1 启动顺序

Architecture._ready()
  → init()：登记成员
  → 创建 System / Model / Utility 节点
  → Utility.init()
  → Model.init()
  → System.init()

Snake 的初步边界

  • 分数、最高分、局数：候选 Model 数据。
  • 存档读写：候选 Utility。
  • 开始、暂停、结束流程：候选 System；是否迁移需由真实复杂度决定。
  • 方向输入、绘制、HUD 节点引用：仍属于场景 Controller / View。

判断口诀：先确认共享需求，再提升到 Architecture；不要因为框架存在，就搬走所有变量。
